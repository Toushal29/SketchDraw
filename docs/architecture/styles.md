# Stylesheet ownership

`src/App.css` is the global stylesheet manifest. Its import order still affects the cascade. `src/App.tsx` loads `/src/styles/app/web-preview.css` directly after the manifest with a Vite root-relative import, avoiding PostCSS resolving the path against the project root as `styles/app/web-preview.css`. This map describes where component rules belong; it does not mean the existing style layers have already been consolidated.

## Component owners

| Component | Shared/base rules | Mobile and tablet rules | Windows rules |
| --- | --- | --- | --- |
| Theme colors and UI tokens | `src/styles/app/theme.css` owns the palette; `src/styles/app/foundation.css` owns shared resets, shell defaults, and primitives. | `src/platform/mobile/ui-refresh.css` defines mobile-only surface variables from the shared tokens. | Use the shared theme tokens; keep Windows-specific application in `src/platform/windows/windows.css`. |
| Workspace shell | `src/features/workspace/workspace-shell.css` owns the workspace shell component. `src/styles/workspace-ui.css` owns shared workspace layout and its explicitly Windows-scoped top-bar adjustments. | `src/platform/mobile/workspace.css`, `src/platform/mobile/mobile.css`, and `src/platform/mobile/ui-refresh.css` own touch workspace layout and focus mode. | `src/platform/windows/windows.css` owns Windows window layout; `workspace-ui.css` contains the Windows top-bar sizing rules. |
| Tool rail and subtool popovers | `src/styles/tools.css` owns shared tool structure; `src/styles/app/toolbar-polish.css` is a legacy visual refinement layer. | `src/platform/mobile/touch-toolbar.css` owns the touch rail, subtools, and their layout. `src/platform/mobile/touch-bars.css` owns touch header, page controls, and shared touch-menu appearance. `src/platform/mobile/quick-style.css` owns quick-style controls. | `src/platform/windows/windows.css` owns the Windows tool deck, collapse controls, and Windows subtool presentation. |
| Canvas navigation and presentation | `src/styles/canvas-navigation.css` owns the minimap and shared presentation controls. | `src/platform/mobile/workspace.css` and `src/platform/mobile/touch-bars.css` own touch placement of canvas controls. `touch-toolbar.css` hides the mobile rail during presentation. | `src/platform/windows/windows.css` owns Windows presentation and fullscreen controls. |

| Canvas web preview | `src/styles/app/web-preview.css` owns the live preview panel and embed dialog; `src/App.tsx` imports it directly after the global stylesheet manifest with a Vite root-relative path. | Use the shared layout and theme tokens. | Use the shared layout and theme tokens. |
| Notes and diagram cards | `src/styles/app/note-cards.css` owns shared canvas cards and notes. | Keep shared behavior here unless a touch-only layout is needed; put that layout in the owning mobile component stylesheet. | Keep shared behavior here unless a Windows-only layout is needed; put that layout in `windows.css`. |

## Shared refinement sheets

`src/styles/app/ui-overrides.css`, `src/styles/app/toolbar-polish.css`, `src/styles/app/canvas-polish.css`, and `src/styles/property-panel-redesign.css` contain later refinement rules. Treat them as existing migration areas, not as the default place for new component base styles. When changing a component, move its base rule to the owner above if that can be done without changing unrelated behavior.

## Platform and cascade rules

- Keep palette hex values in `src/styles/app/theme.css`. Use tokens everywhere else.
- Put mobile/tablet component rules under `src/platform/mobile/` and scope them to `.app-shell:not(.platform-windows)`. Put Windows-only rules under `src/platform/windows/` and scope them to `.app-shell.platform-windows` or the equivalent root platform class.
- Shared rules may use responsive media queries, but platform-specific behavior must include an explicit platform selector.
- `src/platform/mobile/workspace.css`, `mobile.css`, `overrides.css`, `home.css`, and `touch-style.css` now scope their mobile component selectors to a non-Windows app shell. Preserve that boundary when adding rules.
- `src/platform/mobile/touch-toolbar.css` owns touch toolbar and subtool geometry. The positioning helpers in `src/App.tsx` and `src/platform/mobile/MobileCommandBar.tsx` set per-open viewport coordinates as ordinary inline styles; keep static appearance and responsive defaults in CSS.
- Avoid `!important` for ordinary component layout and appearance. The remaining CSS uses are limited to state rules for Windows-only visibility, read-only hiding, and switching quick-style mode children. Prefer a stronger scoped state selector when extending those components.
- Do not add another late global override for a component already owned above. Edit the owner, then remove the superseded declaration where behavior is verified. Component styles imported from the owning TSX should not also be repeated in `App.css`.
- Keep the current `src/App.css` order in mind until the imported styles are consolidated. The manifest links here so ownership can be checked before adding a rule.
